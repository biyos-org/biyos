group types Types
text Five types name the numbers the calls take, so a number means the same in every language: an index, a count or a hook id is a `BIYOS_index`, any other integer a `BIYOS_int`, an offset, a count of entries or a total of terms a `BIYOS_offset`, a value a `BIYOS_real`, and a set of parts of a flags option a `BIYOS_mask`. Every handle is an opaque pointer, made and freed by the calls named below, and a program never looks inside it.

type BIYOS_index
summary An index or a count of items: variables, functions, constraints, objectives, fields, and the id of a hook.
note A 32-bit signed integer, `int32_t` of `<stdint.h>`, which `biyos/biyos.h` includes. Indices count from 0.
see BIYOS_int BIYOS_offset
since 0.1.0

type BIYOS_int
summary An integer that is not an index: a kind, a sense, a priority, a level, an option id or a version.
note A 32-bit signed integer, `int32_t` of `<stdint.h>`.
see BIYOS_index
since 0.1.0

type BIYOS_offset
summary An offset into an array of terms, a count of entries, or a total of terms.
note A 64-bit signed integer, `int64_t` of `<stdint.h>`, since a model may hold more than $2^{31}$ terms.
see BIYOS_index
since 0.1.0

type BIYOS_real
summary A value: a bound, a constant, a coefficient or an option.
note A `double`. An infinite bound is `BIYOS_INF` or `-BIYOS_INF`.
see BIYOS_index
since 0.1.0

table Infinity
value BIYOS_INF Positive infinity, `INFINITY` of `<math.h>`, which `biyos/biyos.h` includes. `-BIYOS_INF` is minus infinity.
since 0.1.0

table Dense
value BIYOS_DENSE A count of -1 that stands for every variable of the model.
see BIYOS_addcb
since 0.1.0

type BIYOS_mask
summary A set of parts of a flags option, one bit per part.
note A 64-bit unsigned integer, `uint64_t` of `<stdint.h>`. Each part is a macro written as a shift, such as `((BIYOS_mask)1 << 0)`, so an option holds at most 64 parts.
see BIYOS_OPTKND_FLG BIYOS_setenvflgopt
since 0.1.0

type BIYOS_status
summary The status a call returns.
note An `int`: `BIYOS_OK`, which is 0, or a negative error code of [Error codes and events](#sec-codes). No call returns a positive status.
see BIYOS_OK BIYOS_lasterror BIYOS_error
since 0.1.0

type BIYOS_env
summary An environment.
note It holds the options, the hooks and the last error of each thread that calls it. Environments share no state, so separate threads may use separate environments at the same time. Threads may share one too: calls on different models of it may run at the same time, and so may calls that only read one model. A call that changes a model, evaluates it or reads one of its derivative patterns runs alone on that model, a call that changes the environment runs alone on it and its models, and a call that would overlap one of them on another thread fails with `BIYOS_ERR_BUSY`. It is freed only once no other thread is in a call on it or will make one. Any thread may call `BIYOS_interrupt` and `BIYOS_lasterror` on it at any time. [Threads](#sec-threads) gives the rule.
see BIYOS_newenv BIYOS_freeenv
since 0.1.0

type BIYOS_event
summary An event, as a hook receives it.
note It is read with the calls of [Reading an event](#sec-capi-reading) and written as a line with `BIYOS_fmttext` and `BIYOS_fmtjson`, and it is valid only while the hook runs.
see BIYOS_hook BIYOS_getevtknd BIYOS_fmttext
since 0.1.0

type BIYOS_model
summary A model.
note It is made on an environment and holds the variables, functions, constraints and objectives of a problem, and its own values of options.
see BIYOS_newmdl BIYOS_copymdl BIYOS_freemdl
since 0.1.0

type BIYOS_hook
summary A function that receives events.
param evt in The event, valid until the hook returns.
param data in The pointer given to `BIYOS_addenvhook` or `BIYOS_addmdlhook`, as given.
note While the hook runs, its environment and the models made on it are read-only ([Events](#sec-capi-events)).
see BIYOS_addenvhook BIYOS_delenvhook BIYOS_addmdlhook BIYOS_delmdlhook
since 0.1.0

type BIYOS_error
summary The last error of a thread on an environment, as `BIYOS_lasterror` reads it.
note `size` is set by the caller to `sizeof(BIYOS_error)` before the call. New members are added at the end, so a caller built against an older header keeps working.
note `status` is the status the failed call returned, or `BIYOS_OK` if no call has failed.
note `mdl` is the model of the failed call, or null for a call on the environment. It is only an address to compare: the model may since have been freed.
note `msg` is the message of the failed call, or an empty string. It is never null and belongs to the environment.
see BIYOS_lasterror BIYOS_status
since 0.1.0

group linking Linking
text These macros decide how the functions of `biyos/biyos.h` are declared, so that one header serves the shared and the static library on every platform.

table Linking macros
value BIYOS_API Marks every exported function. It is `__declspec(dllexport)` while the library builds on Windows, `__declspec(dllimport)` for its callers there, `__attribute__((visibility("default")))` elsewhere, and empty under `BIYOS_STATIC`.
value BIYOS_STATIC Defined by a caller that links the static library, so that on Windows the functions are not imported from a DLL. When biyos is built with `-DBUILD_SHARED_LIBS=OFF`, a CMake target that links `biyos::biyos` gets it from the library.
value BIYOS_BUILDING Defined by the library's own build. A caller never defines it.
since 0.1.0

group codes Status codes
text A call returns `BIYOS_OK` or a negative code. The hundreds of a code say who is at fault: −100 to −199 the caller, −200 to −299 the model, −300 to −399 user code such as a callback, −400 to −499 resources, −500 to −599 biyos. A new code joins its group and keeps its number for good, so test a group by range rather than by value.
text Besides the codes its entry names, every call that returns a status can return `BIYOS_ERR_NOMEMORY` when an allocation fails and `BIYOS_ERR_INTERNAL` on a fault in biyos, and every call on an environment or a model but `BIYOS_lasterror` and `BIYOS_interrupt` can return `BIYOS_ERR_BUSY` when it would overlap a call on another thread ([Threads](#sec-threads)). A solve outcome is never an error code.

table Status codes
value BIYOS_OK The call succeeded.
value BIYOS_ERR_BADARG The caller passed something the call does not accept: a null pointer, an unknown name, id or index, a value out of range, a call of the wrong kind for its option, or a change to an environment while it delivers an event. The entry of each call says which.
value BIYOS_ERR_BADFILE A file breaks the rules of its format, with a message that names the file and the line.
value BIYOS_ERR_UNSUPPORTED A part of a file that the reader does not handle, with a message that names the part and its line, a model that the format cannot hold, or a callback without the function an evaluation needs.
value BIYOS_ERR_BUSY The environment or the model is in a call on another thread that this call may not overlap, or the model is running a callback and this call would change it, evaluate it or read a pattern ([Threads](#sec-threads)).
value BIYOS_ERR_INUSE An item that another record, a node or a callback uses, so this change of it is refused.
value BIYOS_ERR_CALLBACK A callback returned a negative value, or a value that is not finite when checks are on, and stopped the call that asked for it.
value BIYOS_ERR_NOMEMORY An allocation failed, or a count would pass the largest the model can hold.
value BIYOS_ERR_FILEIO The system will not open, read or write a file.
value BIYOS_ERR_INTERNAL A fault in biyos.
since 0.1.0

group env Environment
text An environment holds the options, the hooks and the last error of each thread that calls it, and every model is made on one. Environments share no state.

function BIYOS_newenv
summary Create an environment.
param env out Receives the environment, with every option at its default and an empty error message; set to null on failure.
return `BIYOS_OK`, with the environment in `*env`.
error BIYOS_ERR_BADARG `env` is null.
note The call keeps no message on failure, since it has no environment yet.
see BIYOS_freeenv BIYOS_newmdl
since 0.1.0

function BIYOS_freeenv
summary Free an environment.
param env in The environment to free, with every string read from it; null does nothing and returns `BIYOS_OK`.
return `BIYOS_OK` once the environment is freed.
error BIYOS_ERR_BADARG `env` delivers an event, or has a model that is not freed, with the message `invalid argument: environment: has a model that is not freed`. The call then frees nothing.
note A call on `env` from another thread refuses the free with `BIYOS_ERR_BUSY`, but nothing refuses a call that starts while the free runs or after it returns: free `env` only once no other thread is in a call on it or will make one ([Threads](#sec-threads)).
see BIYOS_newenv BIYOS_freemdl
since 0.1.0

function BIYOS_lasterror
summary Read the last error of the calling thread on an environment.
param env in The environment.
param err out Receives the status, the model and the message of the last call on `env` that this thread made and that failed; `err->size` must be set first.
return `BIYOS_OK`, with the error in `*err`. If no call has failed, `err->status` is `BIYOS_OK`, `err->mdl` null and `err->msg` empty.
error BIYOS_ERR_BADARG `env` or `err` is null, or `err->size` is smaller than `offsetof(BIYOS_error, msg) + sizeof err->msg`, the size of `BIYOS_error` in 0.1.0. The call then writes nothing.
note The call never keeps an error of its own, so a failed read leaves the last error as it was.
note Each thread reads its own last error: a failure on one thread never replaces another's. The environment keeps the errors of the 256 threads that failed most recently, and dropping one ends the life of its message. If memory runs out on a failure when `env` keeps no error for the thread, no error may be kept for that thread and the read gives `BIYOS_OK`. The failed call's return value still carries its status.
note The message starts with the kind of failure, `invalid argument`, `bad file`, `unsupported`, `busy`, `in use`, `out of memory`, `file access` or `internal error`, and is written for people: branch on the status, not on the text. Successful calls leave it in place, and it is empty after a failure if memory ran out while keeping the message.
note `err->msg` stays valid until the next failed call on `env` from the same thread, until the error is dropped or until `env` is freed. A call that fails inside a hook is the last failure only until that hook returns, and a message read inside a hook stays valid only until the hook returns.
see BIYOS_error BIYOS_status
since 0.1.0

function BIYOS_interrupt
summary Ask the call running on an environment to stop.
param env in The environment.
return `BIYOS_OK` once the request is made.
error BIYOS_ERR_BADARG `env` is null.
note It may run while another thread is inside any call on `env`, even one that changes it, and is the one call a signal handler may make. It counts the request on `env` and returns: it takes no lock, allocates nothing, sends no event and keeps no message. `env` must not be freed while it runs.
note A long call notes the count when it starts, reads it where it checks its time limits and stops with the termination `BIYOS_TRM_STOP` once the count has moved, an outcome rather than an error code. No call is long enough to read it yet.
note A request made before a call starts never stops it, so one made between two calls stops neither, and a call starting on one model leaves alone a request meant for a call running on another. A hook may stop the call that sent its event.
see BIYOS_TRM_STOP
since 0.1.0

group options Options
text An option has a name, an id and a kind. Its kind decides which calls set and get it, and a call of another kind returns `BIYOS_ERR_BADARG`: nothing is converted, so an int option refuses `BIYOS_setenvdblopt`. Every call that takes an option id returns `BIYOS_ERR_BADARG` for an id it does not know, and a failed set leaves the option as it was. [Options](#sec-option-table) lists every option.
text Ranges include their ends and are checked exactly, with no tolerance, and NaN lies outside every range. Setting a deprecated option sets it and sends a warning event; setting a retired option, by any call, returns `BIYOS_ERR_BADARG` with a message that names the option to use instead, and changes nothing, while getting it still gives its value. An option is deprecated before it is retired, and the option to use instead is neither.
text Options have two levels. An option set on an environment is shared by every model made on it, and a model may hold its own value of an option, which it reads before the environment's. Each call that sets or reads an option on the environment has a twin on the model, such as `BIYOS_setmdlintopt` beside `BIYOS_setenvintopt`, which checks the value in the same way. `BIYOS_delmdlopt` drops the model's own value, `BIYOS_delenvopt` returns the environment's value to the default, and `BIYOS_getmdloptsrc` tells where the value a model reads comes from. An option of environment scope is set on the environment only, and every model call on it returns `BIYOS_ERR_BADARG` with a message such as `invalid argument: option 'threads': has environment scope`. `threads` is the one option of this release with environment scope.

table Option kinds
value BIYOS_OPTKND_BOOL A bool, set with `BIYOS_setenvboolopt` and read with `BIYOS_getenvboolopt`.
value BIYOS_OPTKND_INT An int, set with `BIYOS_setenvintopt` and read with `BIYOS_getenvintopt`.
value BIYOS_OPTKND_DBL A double, set with `BIYOS_setenvdblopt` and read with `BIYOS_getenvdblopt`.
value BIYOS_OPTKND_STR A string, set with `BIYOS_setenvstropt` and read with `BIYOS_getenvstropt`.
value BIYOS_OPTKND_ENUM One of a list of values, set with `BIYOS_setenvintopt` and read with `BIYOS_getenvintopt`, each value a macro of the option's group.
value BIYOS_OPTKND_FLG A pair of masks, set with `BIYOS_setenvflgopt` and read with `BIYOS_getenvflgopt`: one forces parts on, the other forces parts off, each part a bit macro of the option's group.

group events Events
text biyos writes nothing to standard output or standard error. It reports through events, and a caller reads them by adding a hook on one kind of event at a lowest level. The hook then receives every event of that kind at that level or a more severe one. The hooks of an environment receive an event in the order they were added, and an event no hook wants is not built. They run one at a time: an event sent from one thread waits while a hook runs for another. A model may have hooks of its own, which receive the events of calls on that model alone, in the order they were added and before the hooks of its environment. They too run one at a time, but beside the hooks of other models and of the environment. Each event biyos sends is listed in [Events biyos sends](#sec-capi-sent).
text While a hook runs, whether it belongs to the environment or to one of its models, the environment delivers an event and is read-only to the hook's thread. The hook may read options, the last error, the event and the models made on the environment. Every call that would change the environment, setting or dropping one of its options, adding or removing a hook, creating a model on it or freeing it, fails with `BIYOS_ERR_BADARG` and the message `invalid argument: environment: is read-only while delivering an event`, and every call that would change, evaluate or free a model made on it or read its derivative patterns fails with `invalid argument: model: is read-only while delivering an event`. Such a failure keeps its message but sends no event, and once the hook returns the last error is again what it was before the hook ran.

table Event kinds
value BIYOS_EVTKND_MSG A message: a level, the module that sent it, a text and fields.
value BIYOS_EVTKND_INV A failed check: the invariant that does not hold, the object it was checked on and the values involved.
value BIYOS_EVTKND_SPAN A phase of a solve beginning or ending: its name and the wall and CPU time.
since 0.1.0

value BIYOS_EVTLVL_INFO Info.
value BIYOS_EVTLVL_WARN Warning.
value BIYOS_EVTLVL_ERR Error, the most severe.

group formatting Formatting an event
text These calls write an event as one line into a buffer the caller gives, as `snprintf` does but with the size before the buffer, and nowhere else. They read only the event, so a hook may call them. When `cap` is at least 1 the call writes at most `cap - 1` bytes of the line, then a NUL; a buffer that is too small receives the start of the line, cut at a byte, which may fall inside a UTF-8 character. When `cap` is 0 the call writes nothing, and `buf` may be null, to learn the length alone.
text The line has no trailing newline. A byte below 0x20 is written as `\n` for a newline, `\t` for a tab and `\u00XX` with lowercase hex digits for any other, so the line never breaks. The time of an event is the wall time since its environment was created, in seconds with six decimals, cut to the microsecond, such as `0.001234` for 1234567 nanoseconds; the decimal point is `.` whatever the locale. These calls take no environment, so a failure keeps no message and sends no event, and a failed call writes nothing.

param cap in The size of `buf` in bytes.
param buf out Receives the line; may be null when `cap` is 0.
param len out Receives the length of the whole line in bytes, without the NUL, whether it fits or not.
return `BIYOS_OK`. The line fits when `*len` is less than `cap`.
error BIYOS_ERR_BADARG `evt` or `len` is null, or `buf` is null while `cap` is not 0.
note The line holds the time, a space, the name of the level, a space, the module and a colon, then a space and the text unless the text is empty, then for each field a space, its name, `=` and its value. Every byte from 0x20 up is written as it is, and nothing is quoted: for a line a program reads, use `BIYOS_fmtjson`.
see BIYOS_fmtjson
since 0.1.0

summary Write an event as a line of JSON.

return `BIYOS_OK`. The line fits when `*len` is less than `cap`.

note The line is one JSON object with the members `time`, `kind`, `level`, `module`, `text` and `fields`, in that order. `time` is a number, written as in text. `kind` is `message`, `invariant` or `span`, and `level` is `debug`, `info`, `warning` or `error`. `fields` is an object holding the fields in their order, each value a string. group model Model
text A model is made on an environment and reports there: a call on the model that fails keeps its message on that environment and sends its error event to the hooks of the model and then to those of the environment, and while the environment delivers an event the model is read-only. The environment cannot be freed while a model made on it is not, so a model never outlives its environment.
text The calls on variables, functions, constraints, objectives and complements take many items at once: a count and arrays of that many entries, or, for the terms of functions, arrays in compressed form. biyos reads them during the call and keeps none of them. A call that fails changes nothing. Items are numbered from 0 in the order they are added, each family on its own, and a count or an index of items is a `BIYOS_index`.
text A call that adds items takes `BIYOS_index *pos` as its last argument. When the call succeeds and `pos` is not null, it receives the index of the first new item, which is the number of items held before the call; the new items follow it in order.
text A call that sets an attribute of a list of items, such as `BIYOS_setvarbndsp`, has a reader that takes the same arguments, its outputs where the setter's inputs are, so the attribute of any list of items is read in one call. A family reader, such as `BIYOS_getvarrg`, reads a range of items instead.
text The model and each variable, function, constraint, objective, indicator, special ordered set, cone and complement may have a name, as [Names](#sec-model-names) describes. A name is not empty, is well-formed UTF-8 and holds no NUL. A C string ends at its first NUL, so a name passed in C never holds one. Names match byte for byte. An item has no name until one is set, and reads as an empty string while it has none.
text Names may repeat: setting a name checks no uniqueness, and several items of a family may hold one name. A lookup never chooses among them: it finds an item only when that item alone holds the name. Every family takes the same four calls, named after its short form, `var`, `fun`, `con`, `obj`, `ind`, `sos`, `cone` or `ccon`, and keeps its names apart from those of the other families.

group variables Variables
text Each variable has a kind and a lower and an upper bound. A bound may be `BIYOS_INF` or `-BIYOS_INF`, and no finite bound is taken as infinite, however large. A lower bound of minus infinity or an upper bound of infinity leaves that side unbounded. A lower bound of infinity, an upper bound of minus infinity and NaN are refused, and so is a bound outside the widest bounds of the variable's kind: 0 and 1 for a binary, minus infinity and infinity for any other kind. Any other pair is kept as given, a lower bound above the upper one included.
text A variable may hold its own absolute and relative tolerance, each finite and at least 0, which stand for the options `feastol_abs` and `feastol_rel` for that variable alone. It holds none until `BIYOS_setvartolsp` sets them, and `BIYOS_delvartolsp` returns it to the options. No call solves a model yet.

value BIYOS_VARKND_SEMICONT Semi-continuous: 0, or any value between its bounds.
value BIYOS_VARKND_SEMIINT Semi-integer: 0, or any integer between its bounds.

group functions Functions
text A function of the variables $x$ is $f(x) = c + \sum_j a_j x_j + \sum_{i \le j} q_{ij} x_i x_j + \varphi(x)$: a constant, linear terms, quadratic terms and a nonlinear part. The nonlinear part is the function's expression ([Expressions](#sec-capi-expressions)) plus the part of every callback that covers it ([Callbacks](#sec-capi-callbacks)), and is zero when it has neither. Constraints, objectives, indicators, cones and complements refer to functions by index, so one function may serve several of them. A function's constant must be finite.
text The terms of many functions travel in compressed form, as three arrays. `cnt` holds one count per function, and `var` and `coef` a variable and its coefficient for each term: the terms of function `j` follow those of function `j - 1`, `cnt[j]` of them. So no count is negative, and the counts add up to the number of terms. A count of entries or a number of terms is a `BIYOS_offset`.
text A reader of terms writes into arrays the caller gives: `cap` is the number of terms the arrays hold, and a call whose terms do not fit is refused. Each reader has a count reader that gives the number of terms first. A null array is skipped.

group quadratic Quadratic terms
text A function is added with no quadratic terms, and three forms add them: `BIYOS_addquadterm` takes coordinates, `BIYOS_addquadtermsp` a list of functions with one count each and `BIYOS_addquadtermrg` a range with one count per function. Each term is a pair of variables `i` and `j` and its coefficient, taken as written, with no factor ½: $x_0^2$ is the pair (0, 0) with the coefficient 1, and $x_0 x_1$ the pair (0, 1) with the coefficient 1. A pair may be given in either order and is kept as `(i, j)` with `i <= j`, a function's pairs sorted by `i`, then by `j`. Each must name variables of the model, appear once for its function in a call and have a finite coefficient. A pair the function already holds adds its coefficient to the one held, which must stay finite, so every call adds $q_{ij} x_i x_j$ to its functions. A term whose coefficient is 0, given or summed, is kept.

group constraints Constraints
text A constraint `lb <= f(x) <= ub` bounds a function of the model. It holds the index of the function and two bounds, and several constraints may share a function. A constraint's bounds follow the rule of a continuous variable's: `BIYOS_INF` or `-BIYOS_INF` leaves that side unbounded, a lower bound of infinity, an upper bound of minus infinity and NaN are refused, and any other pair is kept as given, a lower bound above the upper one included. A constraint whose bounds are equal is an equality, and one whose bounds are both infinite is free.
text A constraint may hold its own absolute and relative tolerance, each finite and at least 0, which stand for the options `feastol_abs` and `feastol_rel` for that constraint alone. It holds none until `BIYOS_setcontolsp` sets them, and `BIYOS_delcontolsp` returns it to the options. No call solves a model yet.

group objectives Objectives
text An objective is a function of the model to minimize or maximize, with a priority, a weight and an absolute and a relative tolerance. Several objectives may share a function, and an objective may use the function of a constraint.
text The objectives are optimized in stages, one for each priority they hold, the lowest priority first. A stage minimizes the weighted sum $\sum w\, s\, f_k(x)$ over the objectives of its priority, where $f_k$ is an objective's function, $s$ is 1 when it minimizes and −1 when it maximizes, and $w$ is its weight. Each later stage keeps every objective of an earlier stage within its tolerances of the optimum found for it, the absolute tolerance in the units of its function and the relative one as a fraction of the size of that optimum. A priority is any `BIYOS_int`. A weight is finite and positive, so the sense alone gives the direction. A tolerance is 0 or more, and `BIYOS_INF` sets no limit. `BIYOS_addobj` takes what defines an objective, its function, sense, priority and weight, as `BIYOS_addcon` takes a function and its bounds; a new objective's tolerances are 0 until `BIYOS_setobjtolsp` sets them. No call optimizes the objectives yet.

table Senses
value BIYOS_OBJSENSE_MIN The function is minimized.
value BIYOS_OBJSENSE_MAX The function is maximized.
since 0.1.0

group indicators Indicators
text An indicator `x[v] = val => lb <= f(x) <= ub` switches a constraint on: when binary variable `v` takes the value `val`, 0 or 1, function `f` must lie within the bounds, and otherwise it is free. An indicator holds the index of its variable, its value, the index of its function and two bounds, numbered from 0 in a table of their own. Its bounds follow the rule of a constraint's, and its function stays shared, so one function may carry several indicators beside its constraints. The variable is binary while an indicator uses it: one that is not is refused, and a change of its kind is refused with `BIYOS_ERR_INUSE`.

group sets Special ordered sets
text A special ordered set holds variables of the model, its members, each with a weight. In a set of type 1 at most one member is nonzero; in a set of type 2 at most two are, and two nonzero members are adjacent in the order of their weights. The weights of a set are finite and distinct, and the members are kept in the order given, whatever their weights. A variable is a member of a set at most once and may belong to several sets.

table Special ordered set kinds
value BIYOS_SOSKND_ONE Type 1: at most one member is nonzero.
value BIYOS_SOSKND_TWO Type 2: at most two members are nonzero, adjacent in the order of their weights.
since 0.1.0

group pwls Piecewise linear functions
text A pwl is a piecewise linear function of one argument, given by its points $(x_0, y_0), \dots, (x_n, y_n)$, with $n \ge 1$, $x_0 < x_1 < \dots < x_n$ and every coordinate finite. It is linear between consecutive points, extends its first and last segments past $x_0$ and $x_n$, and takes the value $y_i$ at $x_i$ exactly. A pwl is data, kept as given: `BIYOS_addpwlnode`, or a `BIYOS_OP_PWL` entry of `BIYOS_addexpr`, applies it to a node, and any number of nodes may apply one pwl. Pwls are numbered from 0 in the order they are added and stay in the model once added. They take no name.

group cones Cones
text A cone places functions of the model, taken in order, in a set of a given kind: $(f_{k_1}(x), \dots, f_{k_d}(x)) \in \mathcal{K}$. The functions are its members and their number $d$ its dimension. A cone holds its kind, its parameters and its members, kept as given, and cones are numbered from 0 in the order they are added. A function may be a member of several cones, and of constraints and objectives as well, but appears once in a cone. The kinds, their member order and their dimensions follow the Conic Benchmark Format, version 3, so a cone of a kind the two share maps member for member.
text A cone may hold its own absolute and relative tolerance, each finite and at least 0, which stand for the options `feastol_abs` and `feastol_rel` for that cone alone. It holds none until `BIYOS_setconetolsp` sets them, and `BIYOS_delconetolsp` returns it to the options. No call solves a model yet.
text Each kind fixes the dimensions its cones may take. The two power cones take one parameter for each of their first $r$ members, a weight $\alpha_i$ that is finite and positive, with $\sigma = \sum_i \alpha_i$; the weights are kept as given and need not sum to 1. Every other kind takes no parameter. In the table, $t$ names the first members and $z$ the rest, and $\lVert z \rVert$ is the Euclidean norm.

table Cone kinds
value BIYOS_CONEKND_NONNEG The nonnegative orthant: every member is 0 or more. Dimension 1 or more.
value BIYOS_CONEKND_SOC The second-order cone of $(t, z)$: $t \ge \lVert z \rVert$. Dimension 1 or more.
value BIYOS_CONEKND_RSOC The rotated second-order cone of $(t_1, t_2, z)$: $2 t_1 t_2 \ge \lVert z \rVert^2$ with $t_1, t_2 \ge 0$. Dimension 2 or more.
value BIYOS_CONEKND_EXP The exponential cone of $(t_1, t_2, t_3)$: the closure of the points with $t_2 > 0$ and $t_1 \ge t_2 \mathrm{e}^{t_3 / t_2}$. Dimension 3.
value BIYOS_CONEKND_DEXP The dual exponential cone of $(t_1, t_2, t_3)$: the closure of the points with $t_3 < 0$ and $\mathrm{e}\, t_1 \ge -t_3 \mathrm{e}^{t_2 / t_3}$. Dimension 3.
value BIYOS_CONEKND_POW The power cone of $(t_1, \dots, t_r, z)$ with weights $\alpha_1, \dots, \alpha_r$: $\prod_i t_i^{\alpha_i} \ge \lVert z \rVert^\sigma$ with every $t_i \ge 0$. Dimension $r$ or more, with $r \ge 1$.
value BIYOS_CONEKND_DPOW The dual power cone of $(t_1, \dots, t_r, z)$ with weights $\alpha_1, \dots, \alpha_r$: $\prod_i (t_i / \alpha_i)^{\alpha_i} \ge (\lVert z \rVert / \sigma)^\sigma$ with every $t_i \ge 0$. Dimension $r$ or more, with $r \ge 1$.
value BIYOS_CONEKND_PSD The semidefinite cone of the symmetric matrices $X$ of order $r$ with no negative eigenvalue. The members are the lower triangle of $X$ column by column, $X_{11}, \sqrt{2} X_{21}, \dots, \sqrt{2} X_{r1}, X_{22}, \sqrt{2} X_{32}, \dots, X_{rr}$, each entry off the diagonal scaled by $\sqrt{2}$ so that inner products are kept. Dimension $r(r+1)/2$ with $r \ge 1$.

group complements Complements
text A complement `lb <= f1(x) <= ub ⊥ f2(x)` pairs two functions of the model: `f1` is bounded, and the sign of `f2` follows where `f1` lies. One of three cases holds: `f1(x) = lb` and `f2(x) >= 0`, `f1(x) = ub` and `f2(x) <= 0`, or `lb < f1(x) < ub` and `f2(x) = 0`. The classical `0 <= f1(x) ⊥ f2(x) >= 0` is the case of the bounds 0 and `BIYOS_INF`, and the mixed complementarity of GAMS and PATH the case where `f1` is one variable. A complement holds the indices of its two functions and two bounds, numbered from 0 in a table of their own. Its bounds follow the rule of a constraint's, and both infinite state `f2(x) = 0`. Its functions stay shared: a function may appear in any number of complements, as both functions of one, and beside constraints and objectives. The bounds of a variable inside `f1` stay and hold beside the complement.
text A complement may hold its own absolute and relative tolerance, each finite and at least 0, which stand for the options `feastol_abs` and `feastol_rel` for that complement alone. It holds none until `BIYOS_setccontolsp` sets them, and `BIYOS_delccontolsp` returns it to the options. No call solves a model yet.

group expressions Expressions
text An expression is a node of the model's graph, an operator applied to its children, and the `BIYOS_OP_` constants number the operators. `BIYOS_attachexprsp` adds an expression $e(x)$ to a function, as its nonlinear part beside the parts of the callbacks that cover it ([Callbacks](#sec-capi-callbacks)): $f(x) = c + \sum_j a_j x_j + \sum_{i \le j} q_{ij} x_i x_j + e(x)$ for a function no callback covers. A node is named by its id, a `BIYOS_offset` counted from 0 in the order the nodes are added. Passing a node's id again shares the node, which is stored once however many parents use it, and each variable has one node. Every constant, coefficient and exponent of an expression is finite. [The expression graph](#sec-graph) describes each operator.
text `BIYOS_addexpr` takes many expressions in one call, in postfix, where each operand comes before the operator that takes it: the form bindings and file readers write. Expression `k` is the `cnt[k]` entries of `code` and `arg` that follow those of expression `k - 1`. An entry's code is a `BIYOS_OP_` constant and its argument a `BIYOS_offset`: for `BIYOS_OP_VAR` the variable, for `BIYOS_OP_NODE` the id of a node the model held before the call, for `BIYOS_OP_PWL` the pwl, and for another operator the number of operands it takes, 0 for `BIYOS_OP_CONST`. The values the operators take, as `BIYOS_addnode` reads them, follow one another in `val` in the order of the entries, expression after expression. Each expression leaves one operand, its top node. A sum that is an operand of a sum built in the same expression is merged into it, and so is a product that is an operand of a product, so $x_0 + (x_1 + x_2)$ becomes one sum of three terms. A node named by `BIYOS_OP_NODE` is used whole. `BIYOS_OP_KEEP`, with the argument 1, makes the operand before it a node of its own, used whole in the same way, so a sum can stay a child of a sum. `BIYOS_OP_REF` names that node again by the position in `code` of the `BIYOS_OP_KEEP` entry, which comes earlier in the same call, so the expressions of one call can share a node they build. Neither takes a value. `BIYOS_getexprsp` writes the expressions of functions back in this form.

group callbacks Callbacks
text A callback computes in user code its part $\gamma_k(x)$ of the nonlinear part of each function $k$ it covers. `BIYOS_addcb` names the functions it covers and the variables it reads, and `BIYOS_setcbf`, `BIYOS_setcbg`, `BIYOS_setcbh` and `BIYOS_setcbhv` give it the code for the values of those parts, their first derivatives, the second derivatives of a weighted sum of them and the product of those with a vector. The constant, linear and quadratic terms of a covered function stay in the model beside the callback. A callback is named by its index, counted from 0 in the order the callbacks are added.
text A callback reads either every variable of the model, when `BIYOS_addcb` is given `BIYOS_DENSE`, or the variables it lists. A listed callback works in the numbering of its list: `x`, `v` and `hv` hold one value for each listed variable, in list order.
text The derivative patterns are coordinates, as `BIYOS_addlinterm` takes terms: `BIYOS_setcbg` takes a covered function and a variable for each entry, `BIYOS_setcbh` two variables. They name variables in the model's numbering, for a listed callback as well, and hold only variables the callback reads. Entries may come in any order and may repeat, and `BIYOS_cbg` and `BIYOS_cbh` write one value for each entry in the order given, the values of a repeated entry summed.
text A function's nonlinear part is its expression plus the part of every callback that covers it. A function may be in any number of callbacks and hold an expression beside them, and a callback lists a function at most once. A function emptied by `BIYOS_clrfunsp` stays covered, and `BIYOS_delfunsp` refuses to delete a covered function. A function leaves its callbacks when `BIYOS_delcbsp` deletes them, and may then be deleted. `BIYOS_delvarsp` refuses to delete a variable a callback lists and renumbers the lists and patterns of the others, so a listed callback keeps reading the variables it was written for. A callback added with `BIYOS_DENSE` reads `x` in the numbering of the model when it was written, so no variable can be deleted while the model has one.
text Each of the four functions is called with a `BIYOS_cbreq`, the array it fills and the callback's `data`. It returns 0 once the array is filled, a positive value when its functions are not defined at `x`, so the solver steps back as it does for a domain error of an expression, and a negative value to stop the call that asked for it. The model is read-only while a callback runs, and a callback runs on one thread at a time. A result found through a callback claims at most `BIYOS_CLM_LOCAL`. The calls of [Evaluation](#sec-capi-evaluation) run callbacks.
text The model keeps the function pointers and `data` as given and never frees `data`. A copy made by `BIYOS_copymdl` shares them with its source, so both call the same code with the same `data`.

group evaluation Evaluation
text The calls of this group evaluate a model's functions and their derivatives at a point, and read the patterns of the derivatives, as a solver does. The first of them after a change of the model builds what they need, timed as the phase `evaluation` of module `model`, with the [exact Hessian pattern](#sec-hessian-exact) of a large element timed within it as the phase `pattern` of module `expr`, and the model keeps it until its next change, so later calls skip the build.
text The Jacobian holds the first derivatives of each function, a row for each function and a column for each variable. Its pattern lists, for each function, the variables it may depend on, sorted. The Hessian of the Lagrangian $\sum_k w_k \nabla^2 f_k(x)$ is symmetric, so its pattern lists the lower triangle alone: for each variable $j$, the variables $i \ge j$ whose entry $(i, j)$ may be nonzero, sorted. An entry is in a pattern when some part of a function may give it a value: a linear or quadratic term, an expression or the pattern a callback declares. It stays in the pattern where its value at a point is 0.
text Each call changes no data of the model, but it runs alone on the model, as a change does, so a call on another thread that would overlap it fails with `BIYOS_ERR_BUSY`. While an evaluation runs a callback, a call from the callback that would change the model, evaluate it or read a pattern fails with `BIYOS_ERR_BUSY` too; one that only reads the model runs.
text A callback that returns a positive value leaves NaN in every output it computes for that call, and the call still returns `BIYOS_OK`, so a solver steps back. A negative value stops the call with `BIYOS_ERR_CALLBACK`, and its message names the callback, the part it was asked for and the value, such as `callback: callback 0: function returned -3`.

error BIYOS_ERR_BADARG `path` is null, `fmt` is not a format, or the environment of `mdl` delivers an event.
error BIYOS_ERR_FILEIO The file cannot be opened or written.
error BIYOS_ERR_UNSUPPORTED The format is read only, or the model holds a part the format cannot carry. When a part cannot be carried, the message names the first record that holds it.
note Each part of the model the format leaves out, such as a tolerance, is a warning event from module `io`, with the field `file`. [File formats](#sec-formats) gives the rules of each format.
note The call sends the span `write` from module `io` ([Events biyos sends](#sec-capi-sent)).

group status Solve status
text Three groups of constants describe how a solve ended. The termination says why the solve stopped, a result status says what a returned point is, the primal and the dual point each having one, and the claim says what was proved. They are kept apart, so a result never says more than its method proved. None of them is an error code: a limit reached or an infeasible model is an outcome, not a failed call. No call returns them yet.
text Terminations are grouped by hundreds, like the error codes: 100 to 199 solved, 200 to 299 stopped early by a limit or by the user, 300 to 399 infeasibility or unboundedness detected, 400 to 499 no progress. A new one joins its group, so test a group by range. For the dual point, feasible means feasible for the dual problem.

table Terminations
value BIYOS_TRM_NONE No solve has ended.
value BIYOS_TRM_OPTIMAL A global optimum was found and proved. It comes only with the claim `BIYOS_CLM_GLOBAL`.
value BIYOS_TRM_LOCAL A local solution: every convergence test held at its tolerance.
value BIYOS_TRM_NEARLOCAL Every convergence test held at its relaxed tolerance, after the strict tolerances were not all met.
value BIYOS_TRM_ITERLIM The iteration limit was reached.
value BIYOS_TRM_TIMELIM The wall time limit was reached.
value BIYOS_TRM_CPULIM The CPU time limit was reached.
value BIYOS_TRM_EVALLIM The limit on function evaluations was reached.
value BIYOS_TRM_STOP The user asked the solve to stop.
value BIYOS_TRM_INFEAS The model was proved infeasible. The dual result status says whether a certificate comes with it.
value BIYOS_TRM_LOCINFEAS The solve reached a local minimum of the infeasibility that is not zero. Nothing proves the model infeasible.
value BIYOS_TRM_UNBND The objective is unbounded below on the feasible set.
value BIYOS_TRM_SLOW Progress stalled before the convergence tests held.
value BIYOS_TRM_NUMERIC Numerical difficulties kept the solve from going on.

group sent Events biyos sends
text A field is a name and a value, both text. The messages so far are an error when a call fails, a warning when a deprecated option is set, the warnings of `BIYOS_readmdl` and `BIYOS_writemdl` from module `io`, and an info message when two compared models differ.
text A call on an environment that fails sends an error message, unless the environment is delivering an event. Its level is `BIYOS_EVTLVL_ERR`, its module `capi`, its text the message `BIYOS_lasterror` reads for the failure, and its one field `code` the returned status as decimal text, such as `-100`, so a hook can tell the group from the range.
text Setting a deprecated option sends a warning message at level `BIYOS_EVTLVL_WARN` from module `core`, with a text such as `option 'old': deprecated in 0.2.0, use 'new'` and the fields `option`, `deprecated` and `replacement`, in that order: the name of the option, the version that deprecated it and the name of the option to use instead. A failed set sends no warning. No option is deprecated yet.
text `BIYOS_cmpmdl` sends an info message at level `BIYOS_EVTLVL_INFO` from module `model` when the two models differ. Its text names the first difference, such as `variable 0: upper bound 1 against 2` or `model name 'a' against none`, and it has no fields.
text An invariant event reports an invariant that does not hold, found by a check the `checking` option runs, and the call then fails. Its level is `BIYOS_EVTLVL_ERR`, its module the module that ran the check, its text the message `BIYOS_lasterror` reads for the failure, and its fields are `invariant`, `object` and `values`, in that order. It is not sent while the environment is delivering an event. A check that fails while biyos is building an event sends no invariant event and does not fail the call: the event being built is not sent, the check's error is dropped, and the last error is left as it was.
text A span event marks a phase beginning or ending: a phase of a solve, such as presolve, or a call whose entry names its span. Phases nest: a phase begun inside another ends before it. Its level is `BIYOS_EVTLVL_INFO`, its module the module that timed the phase, its text the name of the phase, and its fields are `edge`, `wall` and `cpu`, in that order. `edge` is `begin` or `end`. `wall` is the wall time since the environment was created and `cpu` the CPU time the thread sending the event has used, both read as the phase begins or ends and written in nanoseconds as decimal text.
text biyos adds up the time of each phase in a timing tree, nested as phases nest, which no call reads yet. The tree leaves out the time spent delivering span events, so a hook never changes it, but the stamps do not: a phase's time in the tree is its end's `wall` and `cpu` less its begin's, less, for each span event sent between the two, the time from that event's stamps until its hooks return. Those events are the phase's own begin event and the events of the phases inside it. Should the CPU time be unreadable as a phase begins, the call fails with `BIYOS_ERR_INTERNAL`, and the phase neither begins nor sends an event. Should it be unreadable as a phase ends, `cpu` repeats its begin value and the phase counts as using no CPU time. A call whose entry names its span times itself as one phase, in a timing tree of its own that lasts for the call.
