group types Types
text Five types name the numbers the calls take, so a number means the same in every language: an index, a count or a hook id is a `BIYOS_index`, any other integer a `BIYOS_int`, an offset or a total of terms a `BIYOS_offset`, a value a `BIYOS_real`, and a set of parts of a flags option a `BIYOS_mask`. Every handle is an opaque pointer, made and freed by the calls named below, and a program never looks inside it.

type BIYOS_index
summary An index or a count of items: variables, functions, constraints, objectives, fields, and the id of a hook.
note A 32-bit signed integer, `int32_t` of `<stdint.h>`, which `biyos/biyos.h` includes. Indices count from 0.
see BIYOS_int BIYOS_offset
since 0.1.0

type BIYOS_int
summary An integer that is not an index: a kind, a sense, a priority, a level, an option id or a version.
note A 32-bit signed integer, `int32_t` of `<stdint.h>`.
see BIYOS_index
since 0.1.0

type BIYOS_offset
summary An offset into an array of terms, or a total of terms.
note A 64-bit signed integer, `int64_t` of `<stdint.h>`, since a model may hold more than $2^{31}$ terms.
see BIYOS_index
since 0.1.0

type BIYOS_real
summary A value: a bound, a constant, a coefficient or an option.
note A `double`. An infinite bound is `INFINITY` or `-INFINITY` of `<math.h>`.
see BIYOS_index
since 0.1.0

type BIYOS_mask
summary A set of parts of a flags option, one bit per part.
note A 64-bit unsigned integer, `uint64_t` of `<stdint.h>`. Each part is a macro written as a shift, such as `((BIYOS_mask)1 << 0)`, so an option holds at most 64 parts.
see BIYOS_KND_FLG BIYOS_setenvflgopt
since 0.1.0

type BIYOS_status
summary The status a call returns.
note An `int`: `BIYOS_OK`, which is 0, or a negative error code of @sec-codes. No call returns a positive status.
see BIYOS_OK BIYOS_lasterror BIYOS_error
since 0.1.0

type BIYOS_env
summary An environment.
note It holds the options, the hooks and the last error of each thread that calls it. Environments share no state, so separate threads may use separate environments at the same time. Threads may share one too: calls on different models of it may run at the same time, and so may calls that only read one model. A call that changes a model runs alone on that model, a call that changes the environment runs alone on it and its models, and a call that would overlap one of them on another thread fails with `BIYOS_ERR_BUSY`. It is freed only once no other thread is in a call on it or will make one. Any thread may call `BIYOS_interrupt` and `BIYOS_lasterror` on it at any time. @sec-threads gives the rule.
see BIYOS_newenv BIYOS_freeenv
since 0.1.0

type BIYOS_event
summary An event, as a hook receives it.
note It is read with the calls of [Reading an event](#sec-capi-reading) and written as a line with `BIYOS_fmttext` and `BIYOS_fmtjson`, and it is valid only while the hook runs.
see BIYOS_hook BIYOS_getevtknd BIYOS_fmttext
since 0.1.0

type BIYOS_model
summary A model.
note It is made on an environment and holds the variables, functions, constraints and objectives of a problem, and its own values of options.
see BIYOS_newmdl BIYOS_copymdl BIYOS_freemdl
since 0.1.0

type BIYOS_hook
summary A function that receives events.
param evt in The event, valid until the hook returns.
param data in The pointer given to `BIYOS_addenvhook`, as given.
note While the hook runs, its environment and the models made on it are read-only ([Events](#sec-capi-events)).
see BIYOS_addenvhook BIYOS_delenvhook
since 0.1.0

type BIYOS_error
summary The last error of a thread on an environment, as `BIYOS_lasterror` reads it.
note `size` is set by the caller to `sizeof(BIYOS_error)` before the call. New members are added at the end, so a caller built against an older header keeps working.
note `status` is the status the failed call returned, or `BIYOS_OK` if no call has failed.
note `mdl` is the model of the failed call, or null for a call on the environment. It is only an address to compare: the model may since have been freed.
note `msg` is the message of the failed call, or an empty string. It is never null and belongs to the environment.
see BIYOS_lasterror BIYOS_status
since 0.1.0

group linking Linking
text These macros decide how the functions of `biyos/biyos.h` are declared, so that one header serves the shared and the static library on every platform.

table Linking macros
value BIYOS_API Marks every exported function. It is `__declspec(dllexport)` while the library builds on Windows, `__declspec(dllimport)` for its callers there, `__attribute__((visibility("default")))` elsewhere, and empty under `BIYOS_STATIC`.
value BIYOS_STATIC Defined by a caller that links the static library, so that on Windows the functions are not imported from a DLL. When biyos is built with `-DBUILD_SHARED_LIBS=OFF`, a CMake target that links `biyos::biyos` gets it from the library.
value BIYOS_BUILDING Defined by the library's own build. A caller never defines it.

group codes Status codes
text A call returns `BIYOS_OK` or a negative code. The hundreds of a code say who is at fault: −100 to −199 the caller, −200 to −299 the model, −300 to −399 user code such as a callback, −400 to −499 resources, −500 to −599 biyos. A new code joins its group and keeps its number for good, so test a group by range rather than by value. No code exists yet in the user code group.
text Besides the codes its entry names, every call that returns a status can return `BIYOS_ERR_NOMEMORY` when an allocation fails and `BIYOS_ERR_INTERNAL` on a fault in biyos, and every call on an environment or a model but `BIYOS_lasterror` and `BIYOS_interrupt` can return `BIYOS_ERR_BUSY` when it would overlap a call on another thread (@sec-threads). A solve outcome is never an error code.

table Status codes
value BIYOS_OK The call succeeded.
value BIYOS_ERR_BADARG The caller passed something the call does not accept: a null pointer, an unknown name, id or index, a value out of range, a call of the wrong kind for its option, or a change to an environment while it delivers an event. The entry of each call says which.
value BIYOS_ERR_BUSY The environment or the model is in a call on another thread that this call may not overlap (@sec-threads).
value BIYOS_ERR_INUSE An item that another record uses, so this change of it is refused.
value BIYOS_ERR_NOMEMORY An allocation failed, or a count would pass the largest the model can hold.
value BIYOS_ERR_INTERNAL A fault in biyos.
since 0.1.0

see BIYOS_freeenv BIYOS_newmdl

function BIYOS_freeenv
summary Free an environment.
param env in The environment to free, with every string read from it; null does nothing and returns `BIYOS_OK`.
return `BIYOS_OK` once the environment is freed.
error BIYOS_ERR_BADARG `env` delivers an event, or has a model that is not freed, with the message `invalid argument: environment: has a model that is not freed`. The call then frees nothing.
note A call on `env` from another thread refuses the free with `BIYOS_ERR_BUSY`, but nothing refuses a call that starts while the free runs or after it returns: free `env` only once no other thread is in a call on it or will make one (@sec-threads).
see BIYOS_newenv BIYOS_freemdl
since 0.1.0

function BIYOS_lasterror
summary Read the last error of the calling thread on an environment.
param env in The environment.
param err out Receives the status, the model and the message of the last call on `env` that this thread made and that failed; `err->size` must be set first.
return `BIYOS_OK`, with the error in `*err`. If no call has failed, `err->status` is `BIYOS_OK`, `err->mdl` null and `err->msg` empty.
error BIYOS_ERR_BADARG `env` or `err` is null, or `err->size` is smaller than `offsetof(BIYOS_error, msg) + sizeof err->msg`, the size of `BIYOS_error` in 0.1.0. The call then writes nothing.
note The call never keeps an error of its own, so a failed read leaves the last error as it was.
note Each thread reads its own last error: a failure on one thread never replaces another's. The environment keeps the errors of the 256 threads that failed most recently, and dropping one ends the life of its message. If memory runs out on a failure when `env` keeps no error for the thread, no error may be kept for that thread and the read gives `BIYOS_OK`. The failed call's return value still carries its status.
note The message starts with the kind of failure, `invalid argument`, `busy`, `out of memory` or `internal error`, and is written for people: branch on the status, not on the text. Successful calls leave it in place, and it is empty after a failure if memory ran out while keeping the message.
note `err->msg` stays valid until the next failed call on `env` from the same thread, until the error is dropped or until `env` is freed. A call that fails inside a hook is the last failure only until that hook returns, and a message read inside a hook stays valid only until the hook returns.
see BIYOS_error BIYOS_status
since 0.1.0

function BIYOS_interrupt
summary Ask the call running on an environment to stop.
param env in The environment.
return `BIYOS_OK` once the request is made.
error BIYOS_ERR_BADARG `env` is null.
note It may run while another thread is inside any call on `env`, even one that changes it, and is the one call a signal handler may make. It sets a flag on `env` and returns: it takes no lock, allocates nothing, sends no event and keeps no message. `env` must not be freed while it runs.
note A long call reads the flag where it checks its time limits and stops with the termination `BIYOS_TRM_STOP`, an outcome rather than an error code. No call is long enough to read it yet.
note The flag clears when the next call on `env` or on one of its models starts, so a request made between two calls stops neither. A call made by a hook leaves it set, so a hook may stop the call that sent its event.
see BIYOS_TRM_STOP
since 0.1.0

group options Options
text An option has a name, an id and a kind. Its kind decides which calls set and get it, and a call of another kind returns `BIYOS_ERR_BADARG`: nothing is converted, so an int option refuses `BIYOS_setenvdblopt`. Every call that takes an option id returns `BIYOS_ERR_BADARG` for an id it does not know, and a failed set leaves the option as it was. @sec-option-table lists every option.
text Ranges include their ends and are checked exactly, with no tolerance, and NaN lies outside every range. Setting a deprecated option sets it and sends a warning event; setting a retired option, by any call, returns `BIYOS_ERR_BADARG` with a message that names the option to use instead, and changes nothing, while getting it still gives its value. An option is deprecated before it is retired, and the option to use instead is neither.
text Options have two levels. An option set on an environment is shared by every model made on it, and a model may hold its own value of an option, which it reads before the environment's. Each call that sets or reads an option on the environment has a twin on the model, such as `BIYOS_setmdlintopt` beside `BIYOS_setenvintopt`, which checks the value in the same way. `BIYOS_delmdlopt` drops the model's own value, and `BIYOS_getmdloptsrc` tells where the value a model reads comes from. An option of environment scope is set on the environment only, and every model call on it returns `BIYOS_ERR_BADARG` with a message such as `invalid argument: option 'host': has environment scope`. No option of this release has environment scope.

table Option kinds
value BIYOS_KND_BOOL A bool, set with `BIYOS_setenvboolopt` and read with `BIYOS_getenvboolopt`.
value BIYOS_KND_INT An int, set with `BIYOS_setenvintopt` and read with `BIYOS_getenvintopt`.
value BIYOS_KND_DBL A double, set with `BIYOS_setenvdblopt` and read with `BIYOS_getenvdblopt`.
value BIYOS_KND_STR A string, set with `BIYOS_setenvstropt` and read with `BIYOS_getenvstropt`.
value BIYOS_KND_ENUM One of a list of values, set with `BIYOS_setenvintopt` and read with `BIYOS_getenvintopt`, each value a macro of the option's group.
value BIYOS_KND_FLG A pair of masks, set with `BIYOS_setenvflgopt` and read with `BIYOS_getenvflgopt`: one forces parts on, the other forces parts off, each part a bit macro of the option's group.

group events Events
text biyos writes nothing to standard output or standard error. It reports through events, and a caller reads them by adding a hook on one kind of event at a lowest level. The hook then receives every event of that kind at that level or a more severe one. The hooks of an environment receive an event in the order they were added, and an event no hook wants is not built. They run one at a time: an event sent from one thread waits while a hook runs for another. Each event biyos sends is listed in [Events biyos sends](#sec-capi-sent).
text While a hook runs, its environment delivers an event and is read-only to the hook's thread. The hook may read options, the last error, the event and the models made on the environment. Every call that would change the environment, setting one of its options, adding or removing a hook, creating a model on it or freeing it, fails with `BIYOS_ERR_BADARG` and the message `invalid argument: environment: is read-only while delivering an event`, and every call that would change or free a model made on it fails with `invalid argument: model: is read-only while delivering an event`. Such a failure keeps its message but sends no event, and once the hook returns the last error is again what it was before the hook ran.

table Event kinds
value BIYOS_EVT_MESSAGE A message: a level, the module that sent it, a text and fields.
value BIYOS_EVT_CHECK A failed check: the invariant that does not hold, the object it was checked on and the values involved.
value BIYOS_EVT_PHASE A phase of a solve beginning or ending: its name and the wall and CPU time.
since 0.1.0

table Event levels
value BIYOS_LVL_DBG Debug, the least severe.
value BIYOS_LVL_INFO Info.
value BIYOS_LVL_WARN Warning.

group formatting Formatting an event
text These calls write an event as one line into a buffer the caller gives, as `snprintf` does but with the size before the buffer, and nowhere else. They read only the event, so a hook may call them. When `cap` is at least 1 the call writes at most `cap - 1` bytes of the line, then a NUL; a buffer that is too small receives the start of the line, cut at a byte, which may fall inside a UTF-8 character. When `cap` is 0 the call writes nothing, and `buf` may be null, to learn the length alone.
text The line has no trailing newline. A byte below 0x20 is written as `\n` for a newline, `\t` for a tab and `\u00XX` with lowercase hex digits for any other, so the line never breaks. The time of an event is the wall time since its environment was created, in seconds with six decimals, cut to the microsecond, such as `0.001234` for 1234567 nanoseconds; the decimal point is `.` whatever the locale. These calls take no environment, so a failure keeps no message and sends no event, and a failed call writes nothing.

param len out Receives the length of the whole line in bytes, without the NUL, whether it fits or not.
return `BIYOS_OK`. The line fits when `*len` is less than `cap`.
error BIYOS_ERR_BADARG `evt` or `len` is null, or `buf` is null while `cap` is not 0.
note The line holds the time, a space, the name of the level, a space, the module and a colon, then a space and the text unless the text is empty, then for each field a space, its name, `=` and its value. Every byte from 0x20 up is written as it is, and nothing is quoted: for a line a program reads, use `BIYOS_fmtjson`.
see BIYOS_fmtjson

group model Model
text A model is made on an environment and reports there: a call on the model that fails keeps its message on that environment and sends its error event there, and while the environment delivers an event the model is read-only. The environment cannot be freed while a model made on it is not, so a model never outlives its environment.
text The calls on variables, functions, constraints and objectives take many items at once: a count and arrays of that many entries, or, for the terms of functions, arrays in compressed form. biyos reads them during the call and keeps none of them. A call that fails changes nothing. Items are numbered from 0 in the order they are added, each family on its own, and a count or an index of items is a `BIYOS_index`.
text A call that adds items takes `BIYOS_index *pos` as its last argument. When the call succeeds and `pos` is not null, it receives the index of the first new item, which is the number of items held before the call; the new items follow it in order.
text A call that sets an attribute of a list of items, such as `BIYOS_setvarbndsp`, has a reader that takes the same arguments, its outputs where the setter's inputs are, so the attribute of any list of items is read in one call. A family reader, such as `BIYOS_getvarrg`, reads a range of items instead.

group variables Variables
text Each variable has a kind and a lower and an upper bound. A bound may be `INFINITY` or `-INFINITY` of `<math.h>`, and no finite bound is taken as infinite, however large. A lower bound of minus infinity or an upper bound of infinity leaves that side unbounded. A lower bound of infinity, an upper bound of minus infinity and NaN are refused, and so is a bound outside the widest bounds of the variable's kind: 0 and 1 for a binary, minus infinity and infinity for any other kind. Any other pair is kept as given, a lower bound above the upper one included.

value BIYOS_VAR_SEMICONT Semi-continuous: 0, or any value between its bounds.
value BIYOS_VAR_SEMIINT Semi-integer: 0, or any integer between its bounds.

group functions Functions
text A function of the variables $x$ is $f(x) = c + \sum_j a_j x_j + \sum_{i \le j} q_{ij} x_i x_j$: a constant, linear terms and quadratic terms. Constraints and objectives refer to functions by index, so one function may serve several of them. A function's constant must be finite.
text The terms of many functions travel in compressed form, as three arrays. Function `j` of them has the terms from `off[j]` to `off[j + 1] - 1` of `varidx` and `coef`, which hold a variable and its coefficient each. So `off` holds one more offset than there are functions: the first is 0, none is below the one before it, and the last is the number of terms. An offset or a number of terms is a `BIYOS_offset`.
text A reader of terms writes into arrays the caller gives: `cap` is the number of terms the arrays hold, and a call whose terms do not fit is refused. Each reader has a count reader that gives the number of terms first. A null array is skipped.

group quadratic Quadratic terms
text A function is added with no quadratic terms, and `BIYOS_addquadtermsp` and `BIYOS_addquadtermrg` add them. Each term is a pair of variables `i` and `j` and its coefficient, taken as written, with no factor ½: $x_0^2$ is the pair (0, 0) with the coefficient 1, and $x_0 x_1$ the pair (0, 1) with the coefficient 1. A pair may be given in either order and is kept as `(i, j)` with `i <= j`, a function's pairs sorted by `i`, then by `j`. Each must name variables of the model, appear once for its function in a call and have a finite coefficient. A pair the function already holds adds its coefficient to the one held, which must stay finite, so every call adds $q_{ij} x_i x_j$ to its functions. A term whose coefficient is 0, given or summed, is kept.

group constraints Constraints
text A constraint `lb <= f(x) <= ub` bounds a function of the model. It holds the index of the function and two bounds, and several constraints may share a function. A constraint's bounds follow the rule of a continuous variable's: `INFINITY` or `-INFINITY` leaves that side unbounded, a lower bound of infinity, an upper bound of minus infinity and NaN are refused, and any other pair is kept as given, a lower bound above the upper one included. A constraint whose bounds are equal is an equality, and one whose bounds are both infinite is free.

group objectives Objectives
text An objective is a function of the model to minimize or maximize, with a priority, a weight and an absolute and a relative tolerance. Several objectives may share a function, and an objective may use the function of a constraint.
text The objectives are optimized in stages, one for each priority they hold, the lowest priority first. A stage minimizes the weighted sum $\sum_i w_i s_i f_i(x)$ of the objectives of its priority, where $w_i$ is the weight of objective $i$, $s_i$ is 1 when it minimizes and −1 when it maximizes, and $f_i$ is its function. Each later stage keeps every objective of an earlier stage within its tolerances of the optimum found for it, the absolute tolerance in the units of its function and the relative one as a fraction of the size of that optimum. A priority is any `BIYOS_int`. A weight is finite and positive, so the sense alone gives the direction. A tolerance is 0 or more, and `INFINITY` sets no limit. `BIYOS_addobj` takes what defines an objective, its function, sense, priority and weight, as `BIYOS_addcon` takes a function and its bounds; a new objective's tolerances are 0 until `BIYOS_setobjtolsp` sets them. No call optimizes the objectives yet.

table Senses
value BIYOS_MINIMIZE The function is minimized.
value BIYOS_MAXIMIZE The function is maximized.
since 0.1.0

group names Names
text The model and each variable, function, constraint, objective and indicator may have a name, as [Names](#sec-model-names) describes. A name is not empty, is well-formed UTF-8 and holds no NUL. A C string ends at its first NUL, so a name passed in C never holds one. Names match byte for byte. An item has no name until one is set, and reads as an empty string while it has none.
text Names may repeat: setting a name checks no uniqueness, and several items of a family may hold one name. A lookup never chooses among them: it finds an item only when that item alone holds the name. Every family takes the same four calls, named after its short form, `var`, `fun`, `con`, `obj` or `ind`, and keeps its names apart from those of the other families.

group expressions Expressions
text An expression is a node of the model's graph, an operator applied to its children, and the `BIYOS_OP_` constants number the operators. `BIYOS_attachexprsp` adds an expression to a function, as the nonlinear part of $f(x) = c + \sum_j a_j x_j + \sum_{i \le j} q_{ij} x_i x_j + e(x)$. A node is named by its id, a `BIYOS_offset` counted from 0 in the order the nodes are added. Passing a node's id again shares the node, which is stored once however many parents use it, and each variable has one node. Every constant, coefficient and exponent of an expression is finite. @sec-graph describes each operator.
text `BIYOS_addexpr` takes many expressions in one call, in postfix, where each operand comes before the operator that takes it: the form bindings and file readers write. Expression `k` is the entries from `off[k]` to `off[k + 1] - 1` of `code` and `arg`. An entry's code is a `BIYOS_OP_` constant and its argument a `BIYOS_offset`: for `BIYOS_OP_VAR` the variable, for `BIYOS_OP_NODE` the id of a node the model held before the call, and for an operator the number of operands it takes, 0 for `BIYOS_OP_CONST`. The values the operators take, as `BIYOS_addnode` reads them, follow one another in `val` in the order of the entries, expression after expression. Each expression leaves one operand, its top node. A sum that is an operand of a sum built in the same expression is merged into it, and so is a product that is an operand of a product, so $x_0 + (x_1 + x_2)$ becomes one sum of three terms. A node named by `BIYOS_OP_NODE` is used whole.

table Operators
value BIYOS_OP_CONST A constant $c$, with no child.
value BIYOS_OP_VAR A variable $x_j$, with no child.
value BIYOS_OP_SUM $c + a_1 e_1 + \dots + a_n e_n$, with a constant $c$ and a coefficient for each of one or more children.
value BIYOS_OP_PROD $c\, e_1 \cdots e_n$, with a coefficient $c$ and one or more children.
value BIYOS_OP_NEG $-e$.
value BIYOS_OP_DIV $e_1 / e_2$.
value BIYOS_OP_CPOW $e^c$, with a constant exponent $c$.
value BIYOS_OP_POW $e_1^{e_2}$.
value BIYOS_OP_EXP $\exp e$.
value BIYOS_OP_LOG $\log e$, the natural logarithm.
value BIYOS_OP_SQRT $\sqrt{e}$.
value BIYOS_OP_SIN $\sin e$.
value BIYOS_OP_COS $\cos e$.
value BIYOS_OP_TAN $\tan e$.
value BIYOS_OP_ABS $\lvert e \rvert$.
value BIYOS_OP_MAX $\max(e_1, \dots, e_n)$, of one or more children.
value BIYOS_OP_MIN $\min(e_1, \dots, e_n)$, of one or more children.
value BIYOS_OP_ASIN $\arcsin e$.
value BIYOS_OP_ACOS $\arccos e$.
value BIYOS_OP_ATAN $\arctan e$.
value BIYOS_OP_SINH $\sinh e$.
value BIYOS_OP_COSH $\cosh e$.
value BIYOS_OP_TANH $\tanh e$.
value BIYOS_OP_ASINH $\operatorname{arsinh} e$.
value BIYOS_OP_ACOSH $\operatorname{arcosh} e$.
value BIYOS_OP_ATANH $\operatorname{artanh} e$.
value BIYOS_OP_ENT $e \log e$.
value BIYOS_OP_SPOW $\operatorname{sign}(e)\, \lvert e \rvert^c$, with a constant exponent $c > 0$.
value BIYOS_OP_ERF $\operatorname{erf} e$, the error function.
value BIYOS_OP_NODE No operator: in postfix, a node the model already holds, named by its id.

function BIYOS_attachexprsp BIYOS_attachexprrg
summary Add expressions to functions of the model.
param mdl in The model.
param pos in In the `rg` form, the first function of the range.
param n in The number of functions that gain an expression.
param idx in In the `sp` form, the functions, each listed at most once; may be null only when `n` is 0.
param node in The node each function gains, by id; may be null only when `n` is 0.
return `BIYOS_OK` once the expressions are added.
error BIYOS_ERR_BADARG `pos` or `n` is negative, a function is not one of the model or is listed twice, the range ends past the last function, a node is not one of the model, or a function's constant, or a coefficient summed with one the function holds, would not be finite.
note The function of entry `k`, `idx[k]` or `pos + k`, becomes $f + e$, where $e$ is node `node[k]`. The constant, linear and quadratic terms of $e$ join the function's, added as `BIYOS_addlintermsp` and `BIYOS_addquadtermsp` add terms, and the rest becomes the function's expression, or is summed in a new node with the expression it has. An expression that holds no constant leaves the function's as it was.
note The expression is split at its top. Among the terms of its top sum, a constant, $a x_j$, $q x_i x_j$ and $q x_j^2$ move, with negations and constant factors pushed into that sum; any other term stays whole, so no product of sums is expanded. Below the top, a node that other nodes use is kept whole, so a subexpression shared by several functions is stored once.
note A call whose expressions bring new linear or quadratic terms moves the terms and offsets of every function from its lowest such one on, as `BIYOS_addlintermsp` does, so the expressions of many functions are best attached in one call, or a function's right after it is added. An expression that brings no new term moves nothing.
see BIYOS_addexpr BIYOS_clrfunsp BIYOS_addlintermsp BIYOS_addquadtermsp

param n in The number of entries.
param idx in In the `sp` form, the function of each entry; may be null only when `n` is 0.
return `BIYOS_OK` once each function given has the constant 0, no linear or quadratic term and no expression. A function listed more than once is emptied once.
error BIYOS_ERR_BADARG `pos` or `n` is negative, a function is not one of the model or the range ends past the last function.
note The constraints and objectives that use a function keep using it. Its expression's nodes stay in the graph, and other functions that share them keep them.
note An expression's linear and quadratic parts join the function's own, and nothing tells them apart afterwards, so no call takes an expression back from a function: the function is emptied and built again.
note A call moves the terms of every function from the lowest one it lists on, so many functions are best emptied in one call.

group status Solve status
text Three groups of constants describe how a solve ended. The termination says why the solve stopped, a result status says what a returned point is, the primal and the dual point each having one, and the claim says what was proved. They are kept apart, so a result never says more than its method proved. None of them is an error code: a limit reached or an infeasible model is an outcome, not a failed call. No call returns them yet.
text Terminations are grouped by hundreds, like the error codes: 100 to 199 solved, 200 to 299 stopped early by a limit or by the user, 300 to 399 infeasibility or unboundedness detected, 400 to 499 no progress. A new one joins its group, so test a group by range. For the dual point, feasible means feasible for the dual problem.

group sent Events biyos sends
text A field is a name and a value, both text. Two messages exist so far: an error when a call fails and a warning when a deprecated option is set.
text A call on an environment that fails sends an error message, unless the environment is delivering an event. Its level is `BIYOS_LVL_ERR`, its module `capi`, its text the message `BIYOS_lasterror` reads for the failure, and its one field `code` the returned status as decimal text, such as `-100`, so a hook can tell the group from the range.
text Setting a deprecated option sends a warning message at level `BIYOS_LVL_WARN` from module `core`, with a text such as `option 'old': deprecated in 0.2.0, use 'new'` and the fields `option`, `deprecated` and `replacement`, in that order: the name of the option, the version that deprecated it and the name of the option to use instead. A failed set sends no warning. No option is deprecated yet.
text A check event reports an invariant that does not hold, found by a check the `check_lvl` option runs, and the call then fails. Its level is `BIYOS_LVL_ERR`, its module the module that ran the check, its text the message `BIYOS_lasterror` reads for the failure, and its fields are `invariant`, `object` and `values`, in that order. It is not sent while the environment is delivering an event. A check that fails while biyos is building an event sends no check event and does not fail the call: the event being built is not sent, the check's error is dropped, and the last error is left as it was. No call runs a check yet.
text A phase event marks a phase of a solve, such as presolve, beginning or ending. Phases nest: a phase begun inside another ends before it. Its level is `BIYOS_LVL_INFO`, its module the module that timed the phase, its text the name of the phase, and its fields are `edge`, `wall` and `cpu`, in that order. `edge` is `begin` or `end`. `wall` is the wall time since the environment was created and `cpu` the CPU time the process has used, every thread included, both read as the phase begins or ends and written in nanoseconds as decimal text.
text biyos adds up the time of each phase in a timing tree, nested as phases nest, which no call reads yet. The tree leaves out the time spent delivering phase events, so a hook never changes it, but the stamps do not: a phase's time in the tree is its end's `wall` and `cpu` less its begin's, less, for each phase event sent between the two, the time from that event's stamps until its hooks return. Those events are the phase's own begin event and the events of the phases inside it. Should the CPU time be unreadable as a phase begins, the call fails with `BIYOS_ERR_INTERNAL`, and the phase neither begins nor sends an event. Should it be unreadable as a phase ends, `cpu` repeats its begin value and the phase counts as using no CPU time. No call times a phase yet.
